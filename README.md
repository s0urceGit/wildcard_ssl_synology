# Synology Wildcard SSL Automation

Скрипт для автоматического выпуска, установки и продления **Wildcard-сертификатов Let's Encrypt** на устройствах Synology NAS.

Скрипт использует [acme.sh](https://github.com/acmesh-official/acme.sh) и DNS API выбранного DNS-провайдера для прохождения DNS-01 challenge.

После получения сертификат автоматически устанавливается в **Synology DSM**.

Дополнительно скрипт поддерживает установку сертификата в **AdGuard Home**, работающий в Docker / Synology Container Manager.

## Особенности

* **Автоматизация:** интерактивное меню запрашивает необходимые параметры и выполняет остальные операции автоматически.
* **Wildcard-сертификат:** выпускается сертификат для основного домена и `*.domain`.
* **DNS-01 challenge:** проверка домена выполняется через DNS API.
* **Synology DSM:** автоматическая установка сертификата через `acme.sh`.
* **Настраиваемый порт DSM:** по умолчанию используется HTTPS-порт `5001`, но пользователь может указать другой.
* **Отдельный пользователь DSM:** можно указать пользователя, имеющего права на управление сертификатами.
* **AdGuard Home:** установка сертификата в AdGuard Home является опциональной.
* **Docker / Container Manager:** можно указать имя Docker-контейнера AdGuard Home.
* **Настраиваемый каталог сертификатов:** можно указать путь к каталогу, используемому AdGuard Home.
* **Автоматическое обновление:** `acme.sh` автоматически продлевает сертификат.
* **Автоматическое обновление AdGuard Home:** после продления сертификат копируется в указанный каталог и контейнер перезапускается.
* **Без `--force`:** скрипт не принуждает `acme.sh` повторно выпускать уже действующий сертификат.

## Поддерживаемые DNS-провайдеры

Скрипт поддерживает следующие DNS API:

* Reg.ru
* Timeweb Cloud
* Yandex 360
* Beget
* Selectel
* DNS Exit
* Cloudflare

Используемый DNS-провайдер должен позволять создавать и удалять TXT-записи через API.

## Требования

1. Домен, DNS которого обслуживается одним из поддерживаемых провайдеров.
2. API-ключ / API-токен или необходимые учетные данные DNS-провайдера.
3. Включенный SSH-доступ к Synology NAS.
4. Запуск скрипта от имени `root`.
5. Доступ Synology NAS к интернету.
6. Пользователь DSM с правами на управление сертификатами.
7. Для использования AdGuard Home — установленный Docker / Container Manager.

## Быстрый запуск

Подключитесь к Synology NAS по SSH и перейдите в режим суперпользователя:

```bash
sudo -i
```

Скачайте скрипт:

```bash
curl -s -o /root/wildcard_ssl.sh https://raw.githubusercontent.com/s0urceGit/wildcard_ssl_synology/main/wildcard_ssl.sh
```

Сделайте его исполняемым:

```bash
chmod +x /root/wildcard_ssl.sh
```

Запустите:

```bash
/root/wildcard_ssl.sh
```

После запуска скрипт последовательно запросит:

1. Домен.
2. Подтверждение домена.
3. Email для Let's Encrypt.
4. DNS-провайдера.
5. API-токен или учетные данные DNS-провайдера.
6. HTTPS-порт DSM.
7. Пользователя DSM.
8. Пароль пользователя DSM.
9. Нужно ли устанавливать сертификат в AdGuard Home.
10. Путь к каталогу сертификатов AdGuard Home.
11. Имя Docker-контейнера AdGuard Home.
12. Подтверждение начала выпуска сертификата.

## Пример

Если ввести:

```text
example.com
```

скрипт автоматически сформирует:

```text
example.com
*.example.com
```

Для DNS-01 challenge будет использоваться TXT-запись:

```text
_acme-challenge.example.com
```

После успешного прохождения проверки Let's Encrypt выпустит Wildcard-сертификат.

## Настройка Synology DSM

По умолчанию используется HTTPS-порт:

```text
5001
```

При запуске скрипт позволяет указать другой порт.

Например:

```text
Порт DSM HTTPS [5001]: 4001
```

В этом случае скрипт будет использовать:

```text
https://localhost:4001
```

Также скрипт запрашивает отдельные учетные данные пользователя DSM.

Пользователь должен иметь права, необходимые для управления сертификатами DSM.

---

## AdGuard Home

Установка сертификата в AdGuard Home является **опциональной**.

При запуске скрипт спрашивает:

```text
Установить сертификат в AdGuard Home? [Y/n]:
```

Если выбрать `n`, сертификат будет установлен только в Synology DSM.

Если выбрать `y`, скрипт запросит каталог сертификатов:

```text
Путь к сертификатам [/volume1/docker/AdGuard/certs]:
```

и имя Docker-контейнера:

```text
Имя Docker-контейнера [AdGuard]:
```

Например:

```text
/volume1/docker/AdGuard/certs
```

и:

```text
AdGuard
```

После получения сертификата в указанном каталоге будут созданы:

```text
fullchain.pem
privkey.pem
```

При последующем автоматическом продлении `acme.sh` обновит эти файлы и выполнит перезапуск указанного Docker-контейнера.

> Важно: каталог сертификатов должен быть доступен контейнеру AdGuard Home через настроенный volume mount в Container Manager.

## Docker / Container Manager

AdGuard Home может работать через:

* Synology Container Manager
* Docker
* другой Docker-совместимый способ запуска

Скрипт автоматически пытается найти команду `docker`.

Если Docker не найден или указанный контейнер отсутствует, скрипт позволяет продолжить работу без настройки AdGuard Home.

## Автоматическое продление

Let's Encrypt выпускает сертификаты сроком действия 90 дней.

`acme.sh` автоматически проверяет состояние сертификата и выполняет продление, когда оно требуется.

Скрипт **не использует**:

```bash
--force
```

Поэтому повторный запуск скрипта не должен принудительно перевыпускать уже действующий сертификат.

`--force` может быть использован вручную через `acme.sh`, если необходимо принудительно получить новый сертификат.

## Настройка Cron

Для автоматической ежедневной проверки продления можно добавить задачу в системный планировщик DSM.

Выполните команду от имени `root`:

```bash
echo -e "0\t3\t*\t*\t*\troot\texport SYNO_Create=1 && export SYNO_USE_TEMP_ADMIN=1 && /root/.acme.sh/acme.sh --cron --home \"/root/.acme.sh\" > /dev/null 2>&1" >> /etc/crontab && synosystemctl restart crond
```

Задача будет запускаться ежедневно в 03:00.

Если сертификат ещё действителен и продление не требуется, `acme.sh` ничего не изменит.

Если требуется продление:

1. `acme.sh` выполнит DNS-01 challenge.
2. Let's Encrypt выпустит новый сертификат.
3. Новый сертификат будет установлен в DSM.
4. Если включён AdGuard Home, сертификаты будут обновлены в указанном каталоге.
5. Docker-контейнер AdGuard Home будет перезапущен.

## Хранение данных

`acme.sh` сохраняет необходимые параметры для последующего автоматического продления.

Основной каталог:

```text
/root/.acme.sh/
```

Файл настроек аккаунта:

```text
/root/.acme.sh/account.conf
```

Конфигурация конкретного сертификата хранится в отдельном каталоге.

Например:

```text
/root/.acme.sh/example.com_ecc/
```

В этих файлах могут находиться API-токены и другие учетные данные, необходимые для автоматического продления.

**Не публикуйте содержимое `/root/.acme.sh/` в GitHub или других публичных источниках.**

---

## Сертификаты

После выпуска сертификата `acme.sh` хранит его локально.

Для ECC-сертификата каталог может выглядеть следующим образом:

```text
/root/.acme.sh/example.com_ecc/
```

В каталоге находятся, в частности:

```text
example.com.cer
example.com.key
ca.cer
fullchain.cer
```

При использовании AdGuard Home скрипт копирует необходимые файлы в указанный пользователем каталог:

```text
fullchain.pem
privkey.pem
```

## Безопасность

Скрипт запускается от имени `root`, поэтому рекомендуется внимательно проверять его содержимое перед использованием.

Проверить скрипт можно командой:

```bash
less /root/wildcard_ssl.sh
```

или:

```bash
nano /root/wildcard_ssl.sh
```

Не передавайте другим пользователям:

* API-токены DNS-провайдера.
* Пароли DNS-провайдера.
* Пароль пользователя DSM.
* Содержимое `/root/.acme.sh/account.conf`.
* Приватные ключи сертификатов.

---

## Логи

Основной лог `acme.sh`:

```text
/root/.acme.sh/acme.sh.log
```

При возникновении ошибки выпуска сертификата можно посмотреть последние записи:

```bash
tail -100 /root/.acme.sh/acme.sh.log
```

Для дополнительной диагностики можно использовать режим отладки `acme.sh`.

Например:

```bash
/root/.acme.sh/acme.sh --issue \
    --dns dns_timeweb \
    -d example.com \
    -d '*.example.com' \
    --debug 2
```

DNS-плагин необходимо заменить на используемый DNS-провайдер.
